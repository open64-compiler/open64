# H5 MLA memory-hierarchy optimization v1.0

H5 adds an executable cross-head cache-sharing family to the admitted absorbed F32 MLA path. It consumes current MR1/H2 cache/version/alias/lifetime facts, finite H3 costing and separately bound H20 96 GB or 141 GB profiles. It preserves Very High domain semantics, canonical High algorithms and Open64 analyses, structured memory lowering, GPU mapping and the PTX bridge. No MLIR operation interface, mapped-image layout, opcode or tensor-type change is involved.

## Concrete choice and admission

The new opt-in is a version-four High search binding document (`open64.lno-high-search.v4`) with existing `-O3 -LNO:high_search=on:high_apply=on:high_search_bindings=PATH`. Its hierarchy capability is exactly `mla-h5-v1:G1=verified-v8;G2,G4=panel16-two-sweep`; controls schema is `open64.mla-search-controls.v4`, space `mla-h5-space-v1-22`. All other fields retain their v3 meanings. Both H2 cache roles must have proved cross-head accesses, storage versions and invocation lifetimes. The imported H20 snapshot and pinned H3 supplement are required. Missing/stale/unsupported evidence declines to ordinary LNO; no-model/architecture-only and v1-v3 routes retain their previous behavior.

The bounded catalog keeps the twelve original G1 configurations and adds G2/G4 with widths 0,32,128,512,1024. Width zero is complete attention up to 1024 tokens; positive widths must be smaller than the context and satisfy the existing split-tuple scratch-capacity proof. H5 does not enable the old MR2 G2/G4/G8 hypothetical retained-cache families. G8, deeper async/TMA/dequantization changes, quantized Q3/Q6 adaptation and AOT serving selection remain separate gates.

One CTA owns a batch, a head group and a chunk. One complete warp owns each head. A bounded 32-token x 16-column F32 shared panel (2048 bytes) is cooperatively filled once and consumed by all valid heads. Score dots visit latent and rotary columns in source order. Every panel has an unconditional CTA publication barrier and all-consumer release barrier before refill. Padded head warps participate in both; they never access caller data. Cache addresses use the explicit batch owner, never an out-of-range padded head's flattened row.

Per-head scores/weights occupy disjoint local shared slots, with capacity rounded to 32 tokens. Warp max/denominator folds and register broadcasts keep heads separate. Each lane normalizes its own weights before a full-mask warp fence publishes them to its warp. A second latent sweep shares panels across heads; sixteen scalar accumulators retain columns across token slabs. The existing per-head normalized [raw maximum, denominator, latent] tuple ABI and guarded stable rescaling merge remain. Query/value projections, masks, output copies and inter-chunk materialization boundaries remain explicit. Mask-false weighted latent products still execute, including nonfinite behavior; geometric padding is guarded before caller loads/stores. Token reductions retain the existing explicit reassociation requirement.

## Owned costing, budgets and application

For valid w tokens and h heads in a CTA, source cache requests are 4w(2R+D) bytes per group, rather than h times that amount. Queries, masks, output tuples and merge traffic are charged separately. The two latent sweeps are intentional; this is cross-head reuse, not elimination of the second latent sweep. Panel writes include zero-filled padded tokens/columns. Scores/weights, all shared reads/writes, two barriers per panel/slab, the warp fence and warp shuffles are explicit costs. The static shared reservation is 2048 + 4G ceil(W/32)32 bytes. A conservative extra 24 scalar registers/thread beyond the prior envelope pays for accumulator and owner state; actual allocation/spills require H7 evidence.

H3 rounds imported resources, pays finite CTA coverage/queues, setup/launch and local service, and compares physical-unit estimates separately from archived cycle fields. Fewer cache requests do not grant an overlap or occupancy discount. Grouping can lose because of panel/barrier work, fewer CTAs or register pressure. Original G1 remains a legal incumbent. Neither source requests nor model estimates are measured HBM traffic or latency.

The same M3 portfolio and H3 request owner enforce proposal, unique-estimate, deadline and detached-memory caps; the 8 MiB work gate precedes catalog construction. Candidate exploration accepts only owned records and constructs no WN/ST/TY, kernels or compiler subprocesses, and runs no correctness tests/timing/profiling. Only the selected complete executable estimate enters phase two. Fresh H2/source/epoch/profile/model/full-recipe/score validation precedes the existing atomic High transaction. Its mutation epoch, DU/alias/access/dependence/reduction rebuild, rollback and exit checks remain authoritative.

The scalar selected High body is the semantic algorithm view. Its v3 selected schema seals the exact group and H5 descriptor; selected worker High carries the explicit physical panels and collectives. The bridge consumes the fixed v9 detached recipe and full native seals, then uses existing ARRAY/SCF lowering, GPU ownership mapping and PTX. It never searches or chooses a group. WHIRL COMMENT explanations are generated by the owning selection/materialization phases and printed by whirl2c. PREOPT's existing COMMENT restoration workaround remains.

## Qualification and transfer

Required evidence includes both H20 variants, G1/grouped choices, width/direct/split cases, partial head/token/column groups, distinct batches, masks/all-masked/exceptional F32 payloads, scratch/resource refusals, finite budgets, missing/stale proofs/model/device bindings, O-level/default compatibility and rollback. Real native before/after B/T/raw diffs and independent source-interleaved reopens are retained. Correctness execution follows selection and uses WHIRL-derived code against the reference; it is never part of exploration. GPU races, ISA register/spill realization, separate timing/profiling and calibration remain explicit H0/H7 gates. No global-optimum or speedup claim follows from host checks.

Primary owner, successor, independent reviewer and approving lead remain TBD. AOT selection and OpenCTI remain deferred. Earlier design documents and receipts remain immutable.
