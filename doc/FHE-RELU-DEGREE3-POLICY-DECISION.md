# FHE Degree-3 ReLU Policy Decision

Status: policy review required; no coefficients are approved or encoded.

## Purpose

SYNC-3 preserves each `common.relu` and requires a structurally valid
approximation contract before SYNC-4 inserts the mandatory pre-ReLU CKKS
bootstrap boundary. This note separates an authoritative coefficient-generation
procedure from an unreviewed coefficient choice. Until the decision below is
approved, conversion remains fail-closed with `CFHECNN-RELU-002` and publishes
no SecureResNet `.fhe.B`.

## Source Findings

OpenFHE provides two relevant, distinct operations:

1. `EvalBootstrap` refreshes CKKS ciphertext capacity; it does not evaluate
   ReLU. OpenFHE documents bootstrapping as approximate modulus/noise refresh
   and exposes explicit setup, key-generation, and evaluation stages.
2. `EvalChebyshevFunction(func, ciphertext, a, b, degree)` generates and
   evaluates a Chebyshev approximation on a declared interval. Its coefficient
   generator returns `degree + 1` coefficients in Chebyshev basis order
   `T0..Tdegree`; OpenFHE's clear evaluator applies the required half-weight to
   the first coefficient. OpenFHE documents multiplicative depth 4 for degrees
   3-5, or one level less when the interval is exactly `[-1,1]`.

OpenFHE describes this interface for smooth real functions. ReLU is continuous
but nonsmooth at zero, so the API is an implementation mechanism, not evidence
that a degree-3 approximation meets ResNet-20 accuracy. Published standard-CNN
work by Lee et al. instead uses compositions of higher-degree minimax
polynomials to preserve accuracy, while AutoFHE jointly searches activation
choices and network behavior. Neither source establishes one universal cubic
for this captured model.

## Required Approval

The minimum decision is one complete tuple:

```text
basis_and_order
coefficient_generation_tool_and_version
coefficient_storage_dtype_and_rounding
closed_input_interval = [a,b]
out_of_interval_policy
error_norm_and_max_error_bound
evaluation_scheme_and_multiplicative_depth
bootstrap_before_relu = required
post_bootstrap_level_scale_precision_contract
plaintext_resnet20_top1_tolerance
ckks_vs_plaintext_logit_and_top1_tolerance
calibration_and_acceptance_dataset_hashes
```

Recommended review candidate: use OpenFHE's pinned degree-3 Chebyshev generation
procedure first, but do not approve its coefficients until activation-range
calibration determines `[a,b]` and the resulting polynomial passes the declared
ResNet-20 tolerance. Persist the exact generated coefficient bytes and their
SHA-256 in the approximation contract evidence. Bootstrap remains a separate
preceding action with reason `PRE_RELU_REFRESH`.

## Certification Sequence

1. Capture plaintext pre-ReLU activation ranges for all 19 source contexts;
   report per-context extrema and one proposed shared or partitioned interval.
2. Approve interval policy, outlier policy, error norm, and ResNet tolerance.
3. Generate four coefficients with the pinned procedure and record basis,
   order, dtype, tool revision, interval, and checksum.
4. Verify clear polynomial error independently of OpenFHE's generator.
5. Run plaintext polynomial-substituted ResNet-20 and enforce accuracy/logit
   tolerances.
6. Run OpenFHE CKKS bootstrap followed by polynomial evaluation; verify output
   level, scale, precision, and numerical tolerance.
7. Only then replace `CFHECNN-RELU-002` with accepted approximation and CKKS
   planning rows and permit SecureResNet checkpoint publication.
