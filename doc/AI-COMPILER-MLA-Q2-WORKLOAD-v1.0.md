# Q2 MLA phase and workload inference v1.0

November 10, 2026. Supplements [Q1 production v1.0](AI-COMPILER-MLA-Q1-PRODUCTION-v1.0.md), [quantized/paged/TMA design v1.0](AI-COMPILER-MLA-QUANTIZED-PAGED-CACHE-AND-TMA-v1.0.md) and [implementation plan v1.17](AI-COMPILER-OPTIMIZATION-SEARCH-IMPLEMENTATION-PLAN-v1.17.md). Earlier versions and receipts remain unchanged.

## Behavior and authority

Q2 adds read-only native inference of an attention workload's static evaluation geometry and a separate validator for invocation-supplied serving phase. It never identifies decode from Q=1, cache dtype, cache length, a quantizer, an operator count alone, a file/model/value name, or a functional scatter. The same source graph can legitimately execute a decode request or a one-token prefill tail. A multi-query graph can serve prefill, speculative verification, or padded mixed requests.

The production Q1 source and post-PREOPT observers now carry Q2 source facts in their existing owned snapshot. Current standalone buffer-v1 inputs contain no bound serving invocation, so their production phase is explicitly **unknown**. Their dense query/KV evaluation capacities and source cache effects can still be known. This is useful information, not an inference failure. No existing input is rejected because workload recognition is unavailable.

`VHO_tensor_infer_workload` accepts the detached Q1 program and an optional typed invocation witness. For a valid witness it reports per-request prefill, decode, speculative-verify or unknown, plus an aggregate mixed state when all active request phases are known and differ. These are validated declarations under the invocation owner's binding precondition, not proof that an arbitrary JSON label came from a serving engine. `VHO_tensor_revalidate_workload` compares the complete current input and result records against former owned facts. A changed invocation identity, source, visibility, lengths, positions, declaration or result invalidates them.

The native caller must supply the actual current invocation values and join the witness to the recognized source. Q3 still owns live buffer handles, page mapping, cache/scale generations, allocator lifetime, publication, concurrency and adapter integration. No compiler option imports a file or an ST phase hint as trusted engine authority. The standalone `q2-workload` command accepts strict review JSON to exercise this native API, always reports `engine_buffer_binding=false` and `dispatch_eligible=false`, and never writes a native phase certificate. A declaration with Q0 provenance `fixture-intent-not-inferred-from-graph` remains unknown even when its geometry is consistent.

## Source analysis and existing Open64 services

The service is in VHO (`tensor_workload.h/.cxx`), where it analyzes the owned detached program already captured by the native source service. It reuses Q1's complete semantic/type/attribute/storage admission. It recognizes the connected ordered 38-operation absorbed-attention tail, including both score contractions, masked guarded softmax, normalized latent accumulation, projection and attention/LSE results. It checks operand joins, actual input/result roles, ranks, dimensions, mask, cache content roles and normalization guards. Merely containing a rank-four mask or a matmul is insufficient. Multiple attention domains, a changed valid semantic topology, missing role joins or unsupported geometry produce explicit unknown recognition results. This bounded recognizer can be broadened in a separately reviewed revision.

The legacy `DSL_Gatekeeper_Verify_Transformer_Decode_Profile` remains unchanged. Its BHSD functional-append contract requires one query token and equal query/KV heads; it does not describe absorbed MLA with shared latent storage or arbitrary padded/ragged queries. Q2 follows its version/length/position/update consistency discipline without presenting that different profile as an MLA phase certificate. No opcode, WN/ST/TY layout, common tensor trait, source schema or mapped reader/writer contract changes.

Recognized source geometry includes B, H, query capacity, KV extent, latent/rotary widths, actual query/mask/cache value identities and a complete source key. Cache ancestor traversal records dense versus indirect-indexed reads and construction, read-only or functional-index-update effects. When all related scatter indices join one input [B,A] index tensor through reshapes, A is a known update-item count per request. It is **not** an append extent or chronological order until an invocation witness establishes that meaning. A gather alone establishes indirect indexing, not an allocator's paged layout or preferred page size.

| Fact | Source-only result | With checked invocation witness |
| --- | --- | --- |
| Query/KV dimensions | Static dense evaluation capacities | Capacities plus active query/valid lengths per request |
| Engine phase | Unknown | Validated declaration or unknown; aggregate may be mixed |
| Query/key positions | Unobserved | Exact ordered position lists |
| Mask | Opaque runtime mask | Explicit opaque, causal or causal-window witness, checked against actual supplied bits |
| Cache validity at graph entry | Unknown | Explicit history length; not necessarily pre-query history |
| Functional scatter | Index update; item count may be known | Append only with length/order/query joins; otherwise indexed-unknown-order |
| Zero active work | Unobserved | Explicit per-request zero-active-query state; source invocation still executes |
| Reuse, publication, dispatch | Not authorized | Still not authorized by Q2 |

Static KV extent describes the array domain the source actually evaluates. A smaller logical valid length does not prove that masked source loads disappear: Q1 may read/dequantize the full allocated capacity before masking. Likewise, a zero-active-query declaration does not permit skipping source cache construction, updates or other effects. This milestone changes neither native memory behavior nor launches.

## Invocation contract and mathematical checks

The review schema is `open64.mla-workload-invocation.v1`, with exact root fields `schema`, `source_key`, `invocation_id`, `evidence`, `requests`. The source key must match the entire admitted source program. Invocation IDs are bounded ASCII tokens. Supported evidence is `bound-serving-invocation-v1` under the native caller precondition, or the untrusted Q0 fixture-intent spelling. Unknown/missing fields, duplicate keys, embedded NUL, booleans used as integers, unsupported versions, negative/nonintegral/oversized values and malformed masks refuse the entire witness without publishing partial facts. The existing standalone strict bounded parser is reused; JsonCpp remains outside be.so.

Each request has exact fields `request`, `query_begin`, `queries`, `history`, `valid`, `append_tokens`, `window_left`, `phase`, `mask_policy`, `update`, `query_positions`, `key_positions`, `update_positions`, `allowed`. This revision supports at most sixteen requests in dense-padded source storage. The segment offsets enumerate the logical concatenation of active queries, not a replacement physical layout. Packed/ragged physical tensor ingestion is not added.

For request b, query capacity Q and KV capacity L:

- Request ordinals are exactly 0..B-1. Logical offsets satisfy o_0=0 and o_(b+1)=o_b+q_b, with 0<=q_b<=Q. Counts/offsets are bounded; total tokens cannot be substituted for q_b.
- 0<=history_b<=valid_b<=L. History is validity at graph entry, as in Q0. Construction/read-only requires history=valid and no append; construction itself does not prove prefill.
- Position lists have exact cardinalities q_b, valid_b and A_b. Entries are bounded, nonnegative and strictly increasing. Query positions must belong to the key-position domain. Nonzero starting positions support existing prefix/window contexts.
- The supplied boolean mask has exactly H*Q*L entries per request. Every true entry must satisfy q<q_b and k<valid_b, so padded query rows and invalid-key columns are false. All-masked heads/rows are allowed and retain source zero/-inf behavior.
- A causal true entry additionally satisfies key_position[k]<=query_position[q]. A causal-window true entry also requires query_position[q]-key_position[k]<window_left, with positive bounded window size. Restrictive masks may remove additional entries. Opaque visibility keeps phase unknown unless the declaration itself is unknown; it cannot validate a known phase.
- For functional append, A_b equals the source's proved per-request index-update count, valid_b-history_b=A_b, and update_positions[j]=key_positions[history_b+j]. A known nonempty phase additionally requires A_b=q_b and update_positions=query_positions. This establishes logical ordering only, not physical page-slot safety or publication.
- Decode requires exactly one active query; v1 speculative verification requires more than one. Prefill permits one-token tails, prefix reuse and chunks. These consistency conditions validate explicit intent; they do not derive intent from the counts.

An active request whose declaration/evidence is unknown keeps its phase unknown. Any unknown active phase makes the aggregate unknown, while preserving known per-request records. Different known active labels aggregate to mixed. Zero-query segments are individually unknown with reason `zero_active_queries` and do not prevent other active requests from having a common phase. An entirely zero-active-query batch is unknown/zero-active-queries. Ragged records include differences in query count or valid length, including inactive segments. No work classification grants a no-work launch path.

## Native lifetime, comments and two-phase search

Q2 static facts are copied into `DSL_HIGH_QUANTIZED_FACTS`, so the holder's existing activation/generation and exact source/native/operation-join validation control their lifetime. Q1 captures before actual PREOPT, invalidates before mutation, installs the returned root, restores annotations, then captures fresh native and Q2 source records. Facts expire before LNO or subsequent mutation and scope closure. `AI_Q2_WORKLOAD` and `AI_Q2_SEGMENT` traces explicitly report unknown active lengths as -1; native observation does not inspect runtime buffers.

The High builder emits a Q2 WHIRL COMMENT describing capacities, source effects, unknown phase and the proof boundary. The Q1-specific post-PREOPT workaround regenerates the explanation at function entry. The existing whirl2c COMMENT printer emits it into actual generated source. General PREOPT COMMENT retention remains a separate deferred effort. No expression, buffer, precision, guard or loop schedule is changed by workload inference.

The pure service uses vectors/maps/strings and the existing detached validator. It has no native allocator, builder, compiler context, runtime probe, GPU, profiler, JIT, search invocation, candidate transformer or emitter dependency. Default geometry inference is independent of O level. Any future specialization must satisfy its separate serving/representation/dependence/realization gates. Existing estimation-only search, portfolios, convergence/global budgets, selected-only atomic application and reference checks remain unchanged. AOT remains the baseline.

## Validation, risks and transfer

The focused native review command reopens authenticated Q1 High images in separate processes, runs inference and revalidation repeatedly, and checks exact executable identity plus ST/TY counts. Cases cover all ten source graphs, known/unknown declarations, one graph serving both prefill tail and decode, multi-query verification, mixed and ragged active requests, prefix reuse, causal windows, zero segments/batches, opaque masks and arbitrary index order. Malformed/stale versions, source/invocation/result seals, lengths, offsets, positions, masks and append joins must refuse without output. Seven altered-mask scenarios execute the retained unchanged Q1 implementation against eager and independent expanded references, with canaries and immutable inputs. This prevents a workload label from silently changing padded/source behavior.

Production qualification reruns the Q1 backend matrix and checks Q2 traces/comments in actual High, post-PREOPT and final emitted C. Retained source-before traces and typed High executable keys are compared with Q1; raw High annotation diffs are retained. Legacy FP32/default fallback, Q1 invalidation, selected-reference and estimation-only tests, control/movement assertions and backend symbol/library/consumer closure remain required. Independent final-path replay must use retained sources/tools/inputs without the original build tree. Actual B/T images, raw diffs, generated source, host libraries, manifests, invocation documents, reports and commands are immutable receipt contents.

Focused qualification passes **66 native workload cases** (45 successful positive/unknown reports and 21 expected refusals), plus invocation/mask/result revalidation controls inside each successful native run. Seven altered-mask source executions check 42 returned values against both references. The complete Q1 production matrix passes 15 configurations, 45 compiled emitted host libraries and 270 base result checks. All fifteen source-before full traces and all ten High executable keys agree exactly with Q1; added High explanation comments and their NAME symbols are the intentional raw diff. Seven legacy/native/search tests, 181 control/movement assertions and two real PREOPT invalidation cases remain required in the acceptance receipt. Backend shared dependencies and undefined imports are unchanged, and the pure service object has no native allocator/builder/search/GPU/JSON dependency. Compiler/host evidence does not certify GPU execution.

Known limitations: bounded closed attention recognition; dense-padded physical inputs; source capacities distinct from logical validity; O(H*Q*L) mask-witness checking/sealing; no live serving-engine adapter; no allocator/cache/scale-generation proof; no zero-work launch elimination; no quantized optimized materializer or TMA; no GPU performance evidence. Q2's conditional invocation API is not Q3 engine qualification. Owner, successor, independent reviewer and approving lead remain **TBD** as requested.
