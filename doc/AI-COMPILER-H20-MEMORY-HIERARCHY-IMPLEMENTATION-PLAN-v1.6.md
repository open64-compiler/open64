# H20 memory-hierarchy implementation plan v1.6

This additive revision preserves [v1.5](AI-COMPILER-H20-MEMORY-HIERARCHY-IMPLEMENTATION-PLAN-v1.5.md), the H4 GEMM delivery and all earlier plans. [H5 MLA v1.0](AI-COMPILER-H5-MLA-HIERARCHY-v1.0.md) defines the new focused executable cross-head-reuse delivery. H20 96 GB and 141 GB remain separate immutable device/resource/profile bindings, never aliases for H200 or an ISA name.

| Phase | Concrete implementation and acceptance |
| --- | --- |
| H5a admission | Version-four source/search binding and immutable 22-entry capability catalog. Require O3 active-PU canonical MLA, numerical permission, current owned H2 latent/rotary reuse/version/lifetime facts, imported H20 and pinned H3. Preserve v1-v3 and unknown/no-model fallback. |
| H5b detached comparison | Keep original G1 configurations; add only implemented G2/G4 panel16 recipes at direct/32/128/512/1024 widths. Count real requests and padded shared/register work, CTA coverage, collectives and existing tuple/merge traffic. Share M3/H3 finite proposal/unique/deadline/memory controls, with no candidate WN/ST/TY or execution. |
| H5c selected application | Revalidate one fixed winner against fresh H2/source/epoch and full model/device/recipe/score. Seal the exact group in selected schema v3 and the bridge's fixed v9 recipe. Use existing atomic High construction, rollback and analysis invalidation/rebuild. |
| H5d physical realization | In selected worker High, generate cooperative 32x16 cache panels, unconditional CTA publication/release, warp-per-head score/weight ownership and scalar latent retention. Preserve token/head/column/mask guards, private tuple ABI, guarded stable merge and explicit numerical policy. Reuse existing Mid ARRAY/SCF lowering, Low ownership mapping and PTX. No emitter-side policy. |
| H5e software qualification | Real production count/resource/model checks, both H20 variants, short/long and tails, G1/grouped outcomes, isolated estimation, selected-only construction, source-interleaved native before/after images/raw diffs and WHIRL-derived reference execution. Missing/stale evidence, budgets, O-levels, rollback and default paths remain separate checks. |
| H0/H7 hardware gate | Execute on actual H20, run sanitizer/race checks, inspect ISA/resources/spills and collect separate timing/profiling for calibration. Software evidence is not a GPU correctness or speedup claim. |

The scalar selected High checkpoint remains the serial semantic view; worker High contains actual shared panels and collectives. Immediate worker before/after checkpoints surround the selected construction in the same fresh driver-owned PU, using isolated native child writers. Generated COMMENTs describe the chosen group, panel ownership, padding, publication/release, local score/weight allocation, partial tuple and merge; the PREOPT COMMENT workaround remains.

Main risks are extra shared traffic/barriers, fewer CTAs, register allocation/spills, aggregate transaction assumptions and bad calibration. The H3 resource model may retain G1. Existing scratch capacity can reject narrow chunks for large latent ranks, particularly ragged contexts; refusal must not allocate unproved backing or change the serving ABI. G8, full-cache retention, deeper async/TMA pipelines, quantized Q3/Q6 adaptation, unsupported general canonical MLA forms and AOT selection remain separate work. OpenCTI remains deferred. Transfer roles remain TBD.
