# H20 memory hierarchy implementation plan v1.4

2026-11-12. This additive revision preserves [v1.3](AI-COMPILER-H20-MEMORY-HIERARCHY-IMPLEMENTATION-PLAN-v1.3.md)
and the original [H0-H8 plan](AI-COMPILER-H20-MEMORY-HIERARCHY-IMPLEMENTATION-PLAN-v1.0.md).
The [H3 specification](AI-COMPILER-H3-MOVEMENT-COSTING-v1.0.md) defines the concrete
cost, input, search and selected-validation contracts. H1/H2 software evidence
remains the baseline; H0/H7 real-device qualification remains open.

| H3 delivery | Implementation |
| --- | --- |
| Physical-unit model | Separate ns components and four explicit cache/service scenarios; H2 source bytes unchanged; no cycle/TC-rate substitution |
| Immutable calibration supplement | Strict versioned, pinned external input bound to complete H20/profile/condition/toolchain/budget identity, imported once before native input |
| Family projections | Existing GEMM D/S1/T2, executable G1 MLA plus analysis-only MR2 grouped hypotheses, LN2/LN4 centered recipes and conditional R2 direct/staged comparison |
| Resource and finite-work effects | Imported rounded RF/shared residency, device-wide bandwidth, per-SM compute/issue/local work, coverage/tails, startup/release and finite fetch queues |
| Convergence | Existing deterministic finite portfolio plus shared request/site unique, proposal, detached-memory and deadline caps; compatible cached estimates count once |
| Selected-only application | Fresh native/H2/device/model binding before one existing selected materializer; COMMENT explanations, atomic rollback/invalidation and fallback retained |
| Software qualification | Independent cost/traffic/budget oracles; both H20 variants; actual owner/native/reference and default/fallback/link-boundary checks |

The seed catalog is the implemented catalog, not its Cartesian-product design
superset. Raw/decoded depths, layouts, groups or trees without executable
capability cannot become winners through calibration JSON. Reduction's modeled
winner does not create a new H6 execution path. Imported quantized Q4/Q5 H3
adaptation remains refused pending its serving-aware complete-plan adapter.
General missing canonical routes retain their H2/H4-H6 gate.

Next work proceeds in the original order: H4 GEMM and H5 MLA materializers can
consume these costs only after operation-specific legality/resource/lifetime
qualification; H6 completes missing LN/Reduction routes; H7 binds physical GPU
inventory, correctness/race checks and separate timing/profiling to the exact
compiler/model/code context. Model assumptions and predictions must be compared
with hardware evidence, never promoted into measured results. H8 acceptance
requires those applicable gates and explicit remaining unknowns. AOT selection,
OpenCTI integration and personnel transfer assignments remain deferred/TBD.
